# session-ram-v1 observation candidate

Only explicitly selected `native_ledger_mode=session-ram-v1` enables the new driver argument and Hub/host finalization path. Serial and existing async defaults retain their previous behavior. No new native pair, ROS qualification or Gazebo run is authorized by source/build acceptance.

The single native thread retains complete ordered `LedgerRecord` values; Packet/Sniff/Drop/Node use the existing primitive representation. Raw fields are still constructed at capture. The captured actual simulation and monotonic stamps are retained until END or handled-exception prefix writing. Primitive capture stamps are now taken at the primitive callback entry, slightly earlier than serial's timestamp after field-string formatting. This is an observation-boundary change, not a promise of identical wall timestamps. Counts/fields/order and PCAP/RX/STEP/ACK remain subject to the separately admitted fixed native pair review.

The compiler verified `sizeof(LedgerRecord)==136` for this ABI. Storage reserves32,000,000 records before READY. The8GiB conservative retained-ledger capacity accounting includes all reserved record storage, the ledger object,64KiB fixed stream/deque bookkeeping allowance, each stored string capacity (including SSO conservatively) and64 bytes per string allocation/alignment allowance. It is not process RSS. Exhaustion raises failure; handled cleanup writes the captured prefix and failed status rather than dropping records silently.

At actual END the Hub records one completion-acceptance deadline, `min(END monotonic+90s, host absolute700s deadline)`. Native wait, evidence copy and Hub result acceptance share it. It is a post-stop evidence window, not a deduction from original boot cleanup90. The unchanged runner stop/UUID/physical/seal/drain procedures do not acquire extra autonomous time. Native and Hub default10/15-second waits are retained outside this opt-in path.

The90-second deadline is a Hub completion acceptance bound, not a hard real-time guarantee for synchronous filesystem calls. Copy checks the deadline between chunks; result acceptance checks both before and after its synchronous write. A completion that crosses the deadline must be recorded FAIL and return nonzero, with retained raw/prefix evidence. The Host only begins its Hub wait after the runner exits; it does not concurrently watch the90-second marker while waiting for the runner. The existing host700-second force-escalation boundary remains the actual outer stop boundary, with original final seal/write overhead reported separately.
